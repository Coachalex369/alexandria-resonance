# The Forge — event-driven multidimensional geometric composition

Status 2026-11-08: research prototype. "Make the invisible work visible. Make the visible
work beautiful." The Forge is an artistic interpretation of observable development activity. It does not claim
to depict an AI's thoughts; every visual element is traceable to a recorded event.

## Demonstration (2026-11-08)

`npm run demo` then open **http://127.0.0.1:4331/packages/forge/session.html** — "Alexandria Resonance · The Forge":
a ten-minute, clearly labelled synthetic development session (`demo/recordings/forge-demo-session.events.jsonl`,
regenerated by `npm run demo:forge-session`) replayed through the same adapter/event interface real sessions use.
One central origin (the objective core, a tesseract that gains internal structure only through verified tests),
Forge (royal purple, 24-cell), Smith (copper-gold crystalline, Workshop temperature and verification states),
Scout (turquoise icosahedron with satellites), Smith's helper and test runner orbiting Smith. Live session and
Finished artwork modes, transport with scrubbing and speed, Jump to finale, agent visibility, provenance
inspection, history, PNG and manifest export, optional music (off by default). Story stages: plan → research →
implement → files → helpers → failing test → diagnose and fix → tests pass → review → complete.

Music v2 (`packages/audio/src/forge-music.js`, `forge-instruments.js`): two clocks (irregular events, stable
musical clock with 16th-note quantization and bar-boundary tempo changes), shared key and chord regions with
voice leading, deterministic file pitches, Forge additive drone with ducking, Smith modal metal strikes (longer
and beating when unverified), Scout glide flute with dead ends and discoveries, core sine rising with the
verified fraction, voice caps, fatigue budget, silence as a state, convergence at task end. 22 tests.

## Independence from Claude Code and the presentation layer

The geometry engine (`packages/geometry`) and the composition engine (`packages/forge/src`: composer,
ripples, fingerprint, renderer, lab model) and the music score (`packages/audio/src`) must not depend on Claude
Code, on the event-engine adapters, on the taxonomy package or on any presentation UI. The composer
consumes a generic event record (id, ts, kind, actor, task, payload metadata, optional classification) that any
adapter can produce; Claude Code hooks are one adapter among git, tests and synthetic sources. Identity presets
and mappings are configuration. `packages/forge/test/boundary.test.js` enforces the rule: engine files may import
only from their own package, the geometry package or Node built-ins, may not mention Claude Code hook or
presentation specifics, and the composer must run on records that carry no classification and unknown kinds.
Presentation files (`forge.js`, `lab.js`) are the only place where a specific event source or UI is wired in.

## Mathematics

- Rotations are compositions of plane rotations `rotation(n, i, j, θ)`; tests assert orthonormality, determinant
  +1 and length preservation in 3D and 4D, that a zw rotation leaves x and y untouched, and that a rotation
  involving w changes w while a pure xy rotation does not. Nothing is a 3D cube pretending to be 4D.
- 4-polytopes are built from exact coordinates (tesseract ±1; 16-cell ±e_i; 24-cell permutations of (±1,±1,0,0);
  600-cell: 16 half-integer points, 8 unit axes and 96 even permutations of ½(±φ, ±1, ±1/φ, 0)). Edges are the
  shortest pairs; faces are 3-cliques (or squares for the tesseract); cells are 4-cliques (16-cell, 600-cell),
  fixed-coordinate cubes (tesseract) or nearest-six-to-dual-vertex octahedra (24-cell). Tests check
  V/E/F/C = 16/32/24/8, 8/24/32/16, 24/96/96/24, 120/720/1200/600 and Euler–Poincaré V−E+F−C = 0.
- 4D→3D perspective puts the viewer on +w: `f = d / (d − w)`; the near cube of the tesseract is larger than the
  far one (tested). Orthographic drops w. w is kept for depth tinting.
- Platonic solids: counts and Euler characteristic 2, equal edge lengths, unit circumradius, planar ordered
  pentagons for the dodecahedron (faces derived from the edge graph), duals (cube↔octahedron,
  dodecahedron↔icosahedron).

## Event → geometry mapping (configurable, artistic)

`forge-mapping.json` maps taxonomy operations and work categories to operations on a structure:

| Observed activity | Operation | Effect |
|---|---|---|
| research, read, browse | reveal / branch | vertices ignite; growth; Scout structures prefer satellites (branching) |
| planning | scaffold | early internal connections appear |
| create | assemble | vertices ignite, larger growth |
| edit | transform | the existing template rotates in a random plane (existing structure transforms; nothing new is spawned) |
| debugging category, tool failure | distort | a subset of vertices is displaced; tension rises |
| edit while tense | reorganize | relaxation rate rises, tension drops (fixing) |
| test pass | wave + reinforce | graph wave; edges reached gain weight (brighter, thicker, persistent) |
| test fail | wave + weaken | negative wave; a 2-hop region is displaced; edges weaken (flicker, redden) until fixed |
| commit, publish | seal | wave + ring |
| agent.start | spawn | a new structure on the agent orbit, tethered to the parent; arrives from outside |
| agent.stop | dock | moves inward, shrinks, stays (never completes the composition) |
| main turn.stop | settle | ring, relaxation |
| task.end | resolve | distortions relax to zero, spin slows, no new waves, final ring, camera pulls back |

Growth is bounded: accumulated growth crosses thresholds that apply internal stages (connect nearest, subdivide
onto the circumsphere, nest the partner polytope, add a satellite) up to `maxEdges` (900 per structure) and
`maxSatellites` (6); beyond that only motion and colour change. Tests replay 1500 events and check the caps.

Identities (`identities.json`) come from configuration or `actor.agentType`, never from text: Forge (24-cell,
violet, planning/review voices), Smith (cube nested with octahedron, cyan, implementers and test runners), Scout
(icosahedron with satellites, amber, scouts and researchers). `byAgentId` pins a specific agent.

Confidence: colour by inferred work category blends only 35 % into the identity hue (palette "identity +
category"); "identity only" ignores inferred classes entirely. Observed facts (tool, path, test result,
failure, agent) drive geometry; inferred classes only tint.

## Ripples, resonance and empty space

Graph waves travel along a structure's edges at a configured hop speed with a Gaussian crest; several waves on
one structure add with sign (test failures are negative) so they interfere; the blended hue follows the
amplitude-weighted mix. Rings expand into the empty field from the originating structure's screen position; where
two rings overlap, an interference point is drawn in the blended hue. A persistent trace layer (offscreen canvas)
accumulates faint strokes where crests pass and faint arcs from rings, and fades toward the background colour
very slowly (bounded persistence: an equilibrium, never black, never saturating).

## Provenance and inspection

Each node keeps `refs.vertices[i]` and `refs.edges[i]` = `{ eventId, kind, ts, agentId, actorType, taskId, tool,
path, structure, replayIndex, lastEventId… }`. Clicking a vertex shows: structure, identity, agent type and
declared model, seed, growth stage, creating event, last touching event, tool and path, code-structure
identifier when present, incident edges with their weights and origin kinds, the task, the fingerprint and the
replay index. No prompt text, tool input or output is ever present (the schema forbids it; the inspector keeps a
whitelist of payload keys).

## Determinism and export

`fingerprint(events, config)` seeds every random choice. Two replays of the same recording and configuration give
identical `snapshotHash()` (tests and the benchmark both check this, including a 20 000-event replay). "Export
manifest" writes `{ recording, fingerprint, snapshotHash, replayPositionMs, camera, ui }` so a composition can be
reproduced; "Save PNG" exports the current frame. Animation and music export are designed for (the composer is
headless) but not built.

## Performance (measured 2026-11-08, Node 22, Windows 11; Chrome for rendering)

| Measure | Value |
|---|---|
| Composer ingest | 0.30 ms per event (6003 events, 5 agents); worst single event 46 ms (a subdivision) |
| Composer tick | 0.23 ms per tick at 25 structures; 0.34 ms at 37 structures |
| World-vertex transform, all nodes | 6.5 ms per frame at 1218 vertices (25 structures) |
| Heap growth | +18 MB over 6000 events; +57 MB over 20 000 events (37 structures, 5940 edges) |
| Laboratory, 600-cell with faces | 44 fps, 6.5 ms per frame (720 edges, 1200 faces, 4D auto-rotation) |
| Forge page, synthetic session resolved | 60 fps, 3.9 ms per frame (760 edges, 720 faces, 3 structures) |
| Forge page, large recorded session | 60 fps, 5.7 ms per frame (572 edges, 614 faces) |

Adaptive quality: the page drops the additive glow pass after 30 consecutive frames over 14 ms and restores it
after 120 frames under 7 ms; a quality selector scales the backing resolution. Faces are skipped above 1400 per
structure. Waves are capped at 64 and rings at 48.

## Rendering evaluation: Canvas 2D now, WebGL later

Canvas 2D was kept for this phase: no new dependency, the geometry engine is renderer-independent, and measured
frame times stay under 7 ms for every demo. Three.js (MIT, ~600 kB) would give real translucent surfaces, bloom
and thousands of edges at full frame rate, and is the recommended next renderer once compositions exceed roughly
3000 visible edges or when shader-based ripple/heat effects are wanted. The renderer interface to replace is
`render2d.js` only.

## Accessibility

`prefers-reduced-motion` disables auto-rotation and camera orbit on both pages (verified: azimuth stays constant);
a manual "reduced motion" checkbox does the same; audio is off by default, independent of other apps' alerts, and
muted until explicitly unmuted; the inspector and readouts are text; the panel works at phone width.

## Dependencies and licensing

No new runtime dependencies were added for The Forge. Everything is original procedural geometry and synthesis.
Sacred-geometry references (Metatron's Cube, Flower of Life, Platonic solids, polytopes) were studied as
mathematics and symmetry; the figures are generated from coordinates, not copied from any artist's model, and no
symbolic or physical claims are attached.

## Demo verification (Chrome, 2026-11-08)

Live view 60 fps at 2–5 ms per frame; finished artwork 55–60 fps at 3–8 ms; music enabled from a click
(AudioContext running, notes scheduled, no console errors); automatic switch to the artwork when the objective
completes; two "Jump to finale" rebuilds give the same snapshot hash; provenance inspection in the gallery
resolves to the labelled event, file and stage; reduced motion stops the orbit.

## Known limitations

- The hook recording carries no task marks, so the composition forms around prompt/turn boundaries unless marks
  are present; the ETA task linker could supply inferred task boundaries (not wired here).
- The 24-cell subdivision produces 264 vertices quickly; stage pacing may need tuning against real sessions.
- Music timing is driven by event timestamps and a lookahead scheduler; it is not yet quantized to a bar grid
  (see the sound-design consultation and "Next experiments").
- Agent orbit positions are deterministic but not collision-aware; two agents can overlap in projection.
- Faces of 4D structures after subdivision are many small triangles; the renderer skips faces above 1400.
- No WebGL path; glow is a two-pass line trick.
- Demo page: structures can overlap in projection at some camera angles (the camera orbits, so this passes);
  trace accumulation depends on playback speed (faster replays stamp fewer traces per event); music levels and
  budgets are untuned first guesses; `stealVoice` instructions are tracked but stolen notes decay naturally.
- `code.structure` events attach to the latest vertex only; a structure-derived lattice seed does not exist yet.

## As above, so below (2026-11-08)

The second visual-composition prototype replaces "one floating polyhedron per agent" with ONE universe in a shared
coordinate system centred on the objective. Page: `packages/forge/universe.html`. Engines added (renderer-independent,
DOM-free, covered by `packages/forge/test/universe.test.js`, `director.test.js`, `packages/geometry/test/forms.test.js`
and `packages/forge/test/frame.test.js`):

| Module | Role |
|---|---|
| `packages/geometry/src/forms.js` | procedural forms: hexagonal lattice that grows ring by ring, crystals (stacked twisted tapered prisms that gain stages), helix, torus, membrane, mirror through y = 0, incremental branch growth |
| `packages/forge/src/universe.js` | the composer: events to bodies and links in one world graph; bounded growth; heat and verification per vertex; ripples through the whole graph; deterministic (fingerprint PRNG); provenance on every vertex, edge and link |
| `packages/forge/src/director.js` | camera director: grounded, curiosity, revelation, expansion, completion; advanced by composition milestones with a progress fallback; reduced-motion poses; manual override; ground and overview poses |
| `packages/forge/src/frame.js` | FrameBuilder: world-space lines, triangles, points and rings as typed arrays (the renderer contract) |
| `packages/forge/src/render-gl.js` | Three.js adapter: fat lines in three width buckets, additive translucent faces, soft point sprites, UnrealBloom (toggle), screenshots |

**Spatial composition (Stage 1).** The reference plane y = 0 is a hexagonal lattice whose rings appear as planning
accumulates (`universe.plane.ringThresholds`); the rings nearest the origin stay clear (`clearingRings`) and every
other structure grows from a lattice site. The origin (the objective) sits at site 0 and gains one subdivision and
one connection pass as tests pass and commits land. A four-dimensional field (the main identity's 4-polytope, the
24-cell by default) turns in the xw, zw and xy planes through the origin, so its projection has vertices above and
below the plane. Agents arrive as small solids (seeds) at home sites chosen deterministically (golden-angle sectors
three rings out; children one site from their parent), linked to their spawner (collaboration links).
Implementation creates one crystal per file at a free site near the agent's home: a create raises a first stage out
of the plane, each later edit adds a twisted stage or nests a partner solid (bounded by `maxStages` and `maxEdges`);
the same file always transforms the same crystal. Research grows a root network beneath the plane from the
researcher's home site (reads extend, searches extend and branch; roots never rise above y = -0.15); a failed fetch
is a dead end (a red tip that stops growing); the researcher's return closes live tips back to the nearest lattice
sites (closure links). Reading a file that already has a crystal is review: it lights the crystal and links it to
the reader (Forge's field, or the reader's seed). Tests send a wave through the world graph from each crystal the
actor or its parent built: passing marks the reached region verified, cools it and gives every verified crystal its
reflection beneath the plane (its foundation, rebuilt when the crystal later grows); failing marks the region
unstable and fractures the foundation. Commits seal a translucent membrane over the apexes of the actor's verified
crystals. Completion resolves tension and brightens the origin without making unverified material verified. New
vertices always emerge from existing geometry (offsets relax toward their final place), so nothing arrives from off
screen.

**Camera (Stage 2).** `CameraDirector.update(dt, { milestones, progress, extent, resolved })` returns an orbit pose.
Grounded (low, near, slight drift) leads to curiosity (first agent or first crystal; gentle rotation), then
revelation (first geometry beneath the plane; climbs to look down, then dips below the plane every 48 s), then
expansion (first pass or commit; slow orbit at varying height, distance scaled to the composition's extent), then
completion (a three-quarter view framing the whole). Each phase has a minimum dwell; a progress fallback
(0.18 / 0.38 / 0.62) keeps the arc moving for recordings without those milestones. Dragging or zooming pauses the
director; Ground view, From above and Resume director are in the Camera panel. Reduced motion eases to each phase
pose and rests.

**Music (Stage 4).** The same `Universe.state()` feeds `ForgeSynth.setState`; events go through `onEvent` with
`structural` set for task start, agent start, commits and plan steps so chord regions advance on structure.
`ForgeSynth.setSpace({ pans, resonance })` (new) pans each agent's voice by where its region sits in the current
view, so the rotating camera moves the sound, and opens the shared lowpass and deepens the reverb with ripple
activity. Drone and core stay centred. Music stays off until enabled and separate from alert sounds.

**Rendering (Stage 5).** Three.js 0.187 (MIT) is a dependency for this branch's renderer adapter only; the Canvas
renderer, the laboratory and the earlier pages are unchanged. Exposure is tuned for additive blending plus bloom
(bloom switches off automatically when a frame exceeds 16 ms for 60 frames). Measured on the demo: 60 fps,
0.3 to 1.1 ms of render time, about 1200 line segments and 900 triangles at the finale.

Limitations: the composition clusters toward the agents' home sectors, so some camera angles show the city off
centre; neighbouring crystals can overlap at the plane; the 4D field's faces are drawn very faintly because their
projections overlap heavily; the director's dwell times are tuned for the ten-minute synthetic recording; music
levels and the depth of panning are first guesses; a reflection is rebuilt rather than animated when its crystal
gains stages after verification.
